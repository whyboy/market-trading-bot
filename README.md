# market-trading-bot

Python 多策略交易项目，先实现 ETF 动量轮动模拟盘，预留实盘执行接口。当前仅确定架构与配置，尚不能交易、调度或推送。

## 结构

```text
main.py                          程序入口
config/
  global.example.json            全局配置模板：时区、行情源、存储、PushPlus
  etf_rotation_strategy.json     策略参数、运行实例、资金、费用、调度
src/market_trading_bot/
  strategies/base.py             策略接口：行情与账户快照 → 目标持仓
  strategies/etf_rotation.py     ETF动量轮动
  models.py                      账户、目标持仓、订单、成交等公共结构
  market.py                      行情适配与交易日历
  execution.py                   仓位转订单、交易检查、模拟执行及未来券商接口
  storage.py                     CSV存储
  report.py                      收益统计、曲线、日报、PushPlus
  runner.py                      配置加载、定时调度、流程协调、防重复执行
data/                            按实例保存运行数据
reports/                         按实例保存日报与图片
requirements.txt                 依赖清单，功能实现时补充
```

## 运行边界

- 策略只输出目标持仓；执行器负责买卖数量、资金与交易限制检查、委托及成交。订单与成交分别记录，为实盘未成交、部分成交及撤单保留空间。
- 一个策略配置可声明多个运行实例；实例通过唯一 `id` 与 `mode` 区分模拟盘和实盘，各自维护独立账本。新增策略增加策略模块与JSON配置。
- 行情缓存可共享；资金、持仓和收益不可跨实例混用。多个策略共用实盘账户的资金分配与订单汇总暂不实现。
- 数据按 `data/<instance_id>/` 保存 `signals.csv`、`orders.csv`、`fills.csv`、`positions.csv`、`equity.csv`、`runs.csv`；报告按 `reports/<instance_id>/` 保存。CSV由单进程协调写入，记录运行状态并防止同一任务重复成交。

## ETF策略口径

- A股交易日北京时间14:30计算并模拟调仓，15:15按收盘价生成日报；收益从账户启动日累计，不补历史回测。
- 动量采用24个历史交易日收盘价加当日14:30价格，共25点；沿用原策略加权对数价格回归及年化收益×拟合优度评分。
- 波动率采用19个历史交易日收盘价加当日14:30价格，共20点、19个对数收益；样本标准差按250日年化。
- 选择动量第一名，即使全部得分为负；目标仓位为目标波动率÷标的波动率，限制在0至100%，极低波动率时为100%。标的不变也按目标仓位调仓。
- 默认初始空仓、资金10万元、双边佣金万二、单笔最低5元、零滑点；通过配置调整。成交按盘中行情模拟，份额与可卖数量遵循标的交易限制。
- 日报展示模拟操作、收盘持仓、当日及累计收益和简单收益曲线。行情失败时不得伪造成交；推送失败不得重新执行交易。

## 配置

复制 `config/global.example.json` 为 `config/global.json`，集中填写行情源与PushPlus Token；实际配置已加入Git忽略。行情源、图片上传方案和券商适配待后续确定，`null`表示尚未选择；当前配置是后续实现的约定。

策略配置中的 `instances` 支持同策略多实例；第一版仅启用 `pap`。未来增加 `pro` 实例及对应券商执行器。金额、费率、滑点、策略参数和执行时间均使用JSON配置，不使用环境配置文件。
